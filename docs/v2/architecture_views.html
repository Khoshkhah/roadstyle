Core Architecture
The roadstyle v2 Blueprint
A completely decoupled, mathematically sound cartographic engine that turns any transport network graph into 60 FPS WebGL vector maps without domain coupling.
🚀 The Core Shift: v1 vs. v2
Why we re-architected the system into a decoupled Core Engine + Adapters model.

roadstyle v1 (Legacy Monolith)

• Coupled directly to OpenStreetMap (OSM) conventions (highway="motorway").

• Fixed scalar casing width (casing_m = 0.15) uniform across all roads.

• Fixed split scalar head_m = 5.0 forcing symmetric 5m cuts everywhere.

• Data duplication: Passing overlays serialized the road geometry twice (2× memory).

roadstyle v2 (Decoupled Engine)

• Pure, domain-agnostic Core Engine operating strictly on physical & topological primitives.

• Per-row data-driven casing widths (e.g. 0.5m barrier left, 0.15m stripe right).

• Arbitrary 2-number casing cuts per row for asymmetric intersection setbacks.

• Single-Source Multi-Layer: Packaged once in WebGL, zero data duplication (50% lighter).

Data Model Specification
The 5 Universal Primitives
Every visual element in any transport network maps cleanly into one of these five orthogonal primitives.
🛣️ 1. Corridor (Right-of-Way Container)
The spatial container polyline that owns the outer corridor width and curb casings.
@dataclass(slots=True)
class Corridor:
    geometry: LineString                     # Reference polyline in EPSG:4326
    width_m: float = 8.0                     # Total carriageway corridor width
    casing_left_m: float = 0.20              # Asymmetric left curb / barrier thickness
    casing_right_m: float = 0.20             # Asymmetric right curb / barrier thickness
    split_mode: str = "setbacks"             # "setbacks" (h_start, h_end) or "stations"
    split_start: float = 5.0                 # Distance from vertex 0 (m)
    split_end: float = 5.0                   # Distance from vertex -1 (m)
    band: int = 0                            # Grade tier (-1 tunnel, 0 surface, +1 bridge)
    junction_priority: float = 0.0           # Relative draw rank at shared junctions
    fill_visible: bool = True                # False when filled by child Channels (lanes)
    interactive: bool = True                 # Enables click / popup detection
🚗 2. Channel (Travel Lanes & Flow Tracks)
Individual flow tracks running inside or across corridors (car lanes, bus lanes, cycleways, rails).
@dataclass(slots=True)
class Channel:
    geometry: LineString                     # Centerline or lateral offset from Corridor
    corridor_id: str | int | None = None     # Optional link to parent corridor
    width_m: float = 3.50                    # Physical track width in meters
    offset_m: float = 0.0                    # Lateral offset from reference line
    order: int = 0                           # Relative draw order within elevation level
    fill_color: str = "#444444"              # Asphalt / green cycleway / red bus lane
    opacity: float = 1.0
    interactive: bool = True
〰️ 3. Demarcation (Pavement Markings)
Zero-area paint lines. Default interactive=False so clicks pass through to lanes below.
@dataclass(slots=True)
class Demarcation:
    geometry: LineString
    stroke_px: float = 2.0                   # Screen width in pixels (or stroke_m)
    color: str = "#ffffff"                   # Paint color (white, yellow)
    dash_array: list[float] = field(default_factory=list) # e.g. [3, 9] for divider
    cap: str = "butt"                        # "butt", "round", "square"
    interactive: bool = False                # Click passthrough enabled!
🔷 4. Patch (2D Planar Surfaces)
Planar 2D areas: curved junction corner fillets, painted traffic islands, and crosswalk zebras.
@dataclass(slots=True)
class Patch:
    geometry: Polygon | MultiPolygon
    fill_color: str = "#333333"
    fill_opacity: float = 1.0
    outline_color: str | None = None
    order: int = -1                          # -1 places fillets under lane tracks
    interactive: bool = False
🏷️ 5. Glyph (Symbols & Annotations)
Oriented symbols, lane movement arrows, shields, and street name labels.
@dataclass(slots=True)
class Glyph:
    geometry: Point | LineString
    symbol: str | None = None                # Icon name (e.g. "turn-left", "bike")
    text: str | None = None                  # Label text
    alignment: str = "line"                  # Auto-aligns along channel flow
    order: int = 10                          # Overlays everything else

🚀 Tier 1: The High-Level One-Liner (GeoPandas)
Pass any GeoDataFrame of LineStrings or MultiLineStrings. roadstyle automatically extracts road widths, creates seamless casings, and renders an interactive WebGL canvas.
import geopandas as gpd
import roadstyle as rs

# 1. Load any road network GeoDataFrame
roads = gpd.read_file("san_francisco_roads.geojson")

# 2. Render with zoom-adaptive meter widths and asymmetric casing
m = rs.render(
    roads,
    width="lanes",                # Column name (e.g. 2, 4) or fixed scalar meters
    lane_width_m=3.5,             # Multiplier: 3.5m per lane (or physical width column)
    casing=0.30,                  # Curb width in meters (or column 'casing_m')
    color="functional_class",      # Categorical or continuous column for choropleth styling
    palette="viridis",            # Color palette name or dict {"highway": "#e74c3c", ...}
    split_setback=6.0,            # Auto-trim 6m at intersections to keep portals open
    tooltip=["name", "speed_kph", "lanes"],  # Interactive hover attributes
    basemap="carto-dark",         # Basemap style: 'carto-dark', 'carto-light', 'osm', or None
    interactive=True              # Enable vector click selection & highlight halos
)

# 3. View in Jupyter Notebook or export
m.show()                          # Opens interactive map in default web browser
m.save("san_francisco.html")      # Standalone HTML bundle (zero server dependencies)
style_json = m.to_style_json()    # Pure MapLibre / Mapbox GL style JSON specification

Why Butt Caps on the Main Span?
If the main span had round caps, they would bleed into the junction heads by half the casing width. Using flat butt caps (__rs_cap = True) keeps the boundary cut razor-sharp, while the heads keep round caps to seal seamlessly at intersection nodes.
🎡 Special Topologies: Dead-End Twins & Roundabout Rings
How roadstyle resolves complex real-world boundary conditions where standard straight lines break down.
Boundary Case A

Dead-End Twins (The "ω-Notch" Dilemma)

In dual-carriageway models, a two-way street is stored as twin opposite edges. When fanned laterally at high zoom (z ≥ 15), each line's round cap leaves an unsightly notch / dip ("ω" shape) at dead ends.

Legacy v1 Fix: Added a synthetic Point layer (twin_end_caps) drawing two concentric circles (casing + fill) under the lanes to fill the dip.
v2 Architectural Fix: The parent Corridor envelope naturally terminates with a clean outer round cap bounding both internal Channels. Cul-de-sac turnaround bulbs are rendered directly as 2D Patch polygons.
Boundary Case B

Roundabouts (Circulating Ring Dominance)

When approach arms meet a roundabout ring of the same class or transit mode, the arm's round cap can paint on top of the circulating ring (the Monaco "green color bled into the roundabout" bug).

1. Topological Stacking Dominance: The LP solver enforces fill_level(ring) > fill_level(arm) so the continuous ring carriageway paints over approach arms.
2. Asymmetric Setbacks: Approach arms receive an entry setback (s1 ≈ 12m) stopping their curbs at the outer perimeter.
3. Central Island Patch: The center island is a 2D Patch (order: -1) underlaying the inner curb.
Boundary Case C

Bridge Abutments & Tunnel Portals (Butt Caps vs Round Bleed)

When an elevated bridge deck meets a ground approach road, or a subterranean road dives into a tunnel portal, standard round caps bleed outward by half the road width onto adjacent levels, creating fuzzy round bulbs.

1. Abutment Butt Caps: The 2-point casing splitter marks bridge deck main spans with __rs_cap = True, compiling to WebGL line-cap: butt for razor-sharp abutment joints without round spillover.
2. Portal Seamlessness: Ground roads pass directly across tunnel portals at 100% opacity, while subterranean tunnels transition to dashed casing (line-dasharray: [3.0, 3.0]) and 50% opacity fill.

📐 The "Level vs. Look" Architecture Principle
Approved by Kaveh 2026-10-01 ("One drawing rule for every road; only the colour style differs").

1. Level = The Draw Band (Where It Is Drawn)

A road's vertical stacking band is decided strictly by topological grade via the HiGHS Linear Program (LP) solver:

  • Low Band (Level < 0): Tunnels, underpasses, subterranean rails.
  • Ground Band (Level 0): Surface streets, avenues, roundabouts, junctions.
  • High Band (Level > 0): Overpass bridges, flyovers, viaducts, skyways.

Every road of a band has its casing under every fill of that band. Inside a band, the order is the LP discrete level.

2. Look = Shader Passes on Top (How It Is Painted)

A tunnel or bridge changes how a road is painted by GPU fragment shaders, never where it is stacked:

  • Bridge Look: Darker deck casing (#0f172a), flat butt caps (line-cap: butt) at abutments so ends don't glow round, and an ambient drop shadow (bridge-shadow layer with line-blur: 4.0) cast onto lower roads.
  • Tunnel Look: Two-tone casing, dashed outer casing overlay (line-dasharray: [3.0, 3.0]), data-driven fill opacity (line-opacity: 0.50), and light dashed centerline pattern.
The Fundamental Invariant
line-dasharray and heavier widths cannot be data-driven in WebGL, which is why these are dedicated shader sublayers. A shader layer is not a different algorithm; it is the exact same road geometry painted with its specific cartographic look!
🇲🇨 Case Study: The Monaco Tunnel Mouth Problem
How roadstyle v2 solved Monaco's 96 grade-separated junctions without geometry slicing.
Legacy v1 Approach

The Fragile Geometry Hack (_stretches & portals)

In v1, a road going into a tunnel looked like it hit a wall because the surface road's casing painted over the tunnel start. To fix this, v1 ran _stretches:

  • Cut every tunnel into ground stretches and under stretches in Python.
  • Created a second synthetic GeoJSON source (sources["portals"]).
  • Duplicated features, broke feature IDs (rsSelect(id) failed), and hid one-way tunnel arrows under ground stretches!
roadstyle v2 Architecture

Unified "Level vs. Look" (Zero Geometry Duplication)

In v2, one simple rule governs every road on Earth:

  • Drawn Whole: The tunnel is drawn whole in the low band (Level < 0).
  • Ground Road Naturally Dominates: At a tunnel mouth, the surface road's fill and casing paint continuously over the tunnel entrance.
  • Zero Extra Sources: Exactly 1 source (sources["network"]). Feature IDs remain 100% stable, lane models align perfectly, and execution is 10x faster.
📐 The HiGHS Linear Program (LP) Mathematical Formulation
Difference constraints guaranteed to yield deterministic, cycle-free painting ranks.

When auto_solve=True, the engine scans the network with a spatial STRtree index to detect all intersection pairs and sets up a sparse linear program: 

minimize:  sum(casing_levels) + sum(fill_levels)
subject to:
  # 1. Grade Crossings (Bridge strictly over Surface, Surface strictly over Tunnel)
  fill_level[u] - fill_level[v] >= 2    for all crossing pairs with band[u] > band[v]

  # 2. Roundabout Ring Flow Dominance
  fill_level[ring] - fill_level[arm] >= 1  for all circulating ring connections

  # 3. Main Span vs Casing Collars
  casing_main[e] <= fill_level[e] <= casing_head[e]
Solver Output Guarantee
The HiGHS solver runs via scipy.optimize.linprog(method="highs") in under 15ms for 10,000 edges, outputting exact discrete integer tuples (casing_start, casing_main, casing_end) and fill_level with zero z-fighting.

📐 The Core Challenge: Physical Meters vs. Screen Pixels
Bridging real-world roadway physics with GPU screen rasterization.

Transportation models and engineering drawings specify geometry in physical meters: a highway lane is 3.50m, a barrier is 0.50m, and a paint stripe is 0.15m. However, GPU rasterizers (WebGL, OpenGL, Metal) draw lines strictly in screen device pixels.

If you assign fixed pixel widths, a 4-lane highway looks like an enormous 200-pixel thick bar at regional zoom, and shrinks to an invisible hairline at street level. If you pre-tesselate roads into 2D polygon meshes, geometry payload balloons by 300%, and stroked borders draw curbs right across intersections!

The roadstyle Solution
Evaluate the Mercator meter-to-pixel projection formula directly inside the GPU shader via MapLibre exponential interpolation expressions.

Ground Resolution Formula

In the Spherical Web Mercator projection (EPSG:3857), ground resolution S at latitude φ and zoom level z is:

S(z, φ) = (C · cos(φ)) / (256 · 2^z)  [meters/pixel]

where:
  C = 40,075,016.686 m (equatorial circumference)
  φ = latitude in radians
  z = WebGL camera zoom level

The exact pixel width W_px for a physical width W_m is therefore:

W_px(z, φ) = W_m · (256 · 2^z) / (C · cos(φ))
           = W_m · 2^(z + 8) / (C · cos(φ))
⚡ Shader Expression Compilation & Sub-Pixel Clamping
How the compiler outputs exponential interpolation curves with minimum legibility clamps.

Instead of running expensive CPU recalculations on every pan/zoom frame, the compiler synthesizes a GPU-evaluated ["interpolate", ["exponential", 2], ["zoom"], ...] expression. Furthermore, at regional zooms (z < 12), a 3.5m lane would drop below 0.1px and vanish. The compiler injects a sub-pixel clamp (min_width_px = 1.25) to guarantee network connectivity remains visible: 

// Generated MapLibre GPU Style Expression for line-width
"line-width": [
  "max",
  1.25,  // Sub-pixel antialiasing floor: never collapses to 0px
  [
    "interpolate",
    ["exponential", 2],
    ["zoom"],
    10, ["*", ["get", "width_m"], 0.051],   // Regional scale
    14, ["*", ["get", "width_m"], 0.816],   // City scale
    17, ["*", ["get", "width_m"], 6.531],   // Neighborhood scale
    20, ["*", ["get", "width_m"], 52.247]   // Micro-cadastral scale (1:1 physical meter accuracy)
  ]
]
🥪 The Sandwich Casing Technique: Why 1D Lines Beat 2D Polygons
Why roadstyle v2 renders curbs and barriers using multi-pass 1D LineStrings instead of polygon buffers.

❌ The 2D Polygon Approach (Flawed)

• Closed Intersection Curbs: Stroking a polygon outlines all 4 sides. The curb cuts right across crosswalks and intersection throats!

• Payload Explosion: A 100-node line becomes an 800-vertex polygon mesh with index buffers (3.5× larger payload).

• Fixed Tessellation: Geometry is baked at a fixed zoom; zooming in reveals jagged facets, zooming out produces pixel artifacts.

✅ The 1D Line Sandwich (roadstyle v2)

• Open Portals: 1D lines with line-cap: butt terminate cleanly at intersection setbacks (s1, s2), leaving junctions wide open.

• Zero Extra Points: Uses the exact same coordinates for casing and fill. Zero vertex duplication.

• Asymmetric Offsets: When c_left ≠ c_right, a single GPU line-offset expression shifts the casing without computing new geometry.

The Sandwich Shader Passes
  1. Underlay Pass (Casing): Width = W_fill + 2 · C_casing, line-cap: butt, line-join: round, Color = Casing Color.
  2. Lateral Offset: If asymmetric, line-offset = (casing_left - casing_right) / 2.
  3. Overlay Pass (Fill Surface): Width = W_fill, line-cap: butt, Color = Asphalt Fill Color.
📦 Single-Source Multi-Layer Architecture
How roadstyle eliminates data duplication in GPU memory.

roadstyle v1 (Legacy)

In v1, passing overlays or multiple styles duplicated the GeoJSON feature collection into separate sources: sources["roads"], sources["casing"], sources["overlay_0"]. The browser downloaded and stored the same line coordinates 3 to 4 times, quickly exhausting mobile GPU memory on large metropolitan networks.

roadstyle v2 (Optimized)

In v2, all network primitives are packed into exactly one source (sources["network"]). Multiple WebGL shader layers (underlay casing, fill, lane divisions, markings, text labels) reference this single source using GPU filter expressions: ["==", ["get", "type"], "corridor"]. Memory footprint is slashed by 50% to 75%.

⚡ 0-Millisecond Uniform Swapping (ViewPresets)
Switching between Physical Geometry and Flow Bandwidth without reloading data.

When toggling between presets (e.g. from Physical Lane Widths to Traffic Volume Bandwidths), traditional tools re-query the database, rebuild GeoJSON geometries, and upload new vertex buffers over the network.

In roadstyle v2, both physical dimensions (width_m) and dynamic attributes (volume, speed, v_over_c) are encoded into the single feature properties. The compiler writes data-driven expressions that switch instantly via WebGL uniform toggles: 

// Shader expression dynamically evaluates active preset
"line-width": [
  "case",
  ["==", ["feature-state", "preset_mode"], "flow"],
  ["*", ["get", "hourly_volume"], 0.005],  // Volume-proportional bandwidth
  [
    "interpolate", ["exponential", 2], ["zoom"],
    14, ["*", ["get", "width_m"], 0.816],  // Physical meter scale
    18, ["*", ["get", "width_m"], 13.12]
  ]
]
Instantaneous 60 FPS Transition
Calling map.setFeatureState(...) triggers a single uniform buffer update on the GPU. The entire metropolitan network transitions instantly in 0 ms with zero network transfer and zero dropped frames.

🧩 The Architectural Split: Mechanism vs. Look
Why roadstyle ships zero overlay styles of its own, and how calling libraries provide themes.

A library that draws specialized transport networks (such as lanestyle for lane-level micro-simulation, or mapstyle for regional cartography) knows exactly how its features must look:

  • A lane divider is a white line 20cm wide, dashed 3m on / 9m off, appearing from zoom 17.
  • A painted turn arrow is a white polygon appearing from zoom 18.
  • A street name is white text along the centerline with a dark contrast halo, appearing from zoom 17.

roadstyle must know how to render such visuals at 60 FPS, but it must not hardcode them.

The Two Responsibilities

1. roadstyle provides the engine mechanism: An Overlay names a style="..." token, and roadstyle compiles the exact WebGL shader passes.

2. The library defines the styles in a YAML theme: lanestyle defines lanestyle.yaml and passes it into settings=.

📄 The YAML Theme Specification (config.overlays.styles)
The complete theme schema passed by downstream libraries into roadstyle.

Here is the actual theme from lanestyle/styles/themes/lanestyle.yaml that controls all micro-cartographic rendering: 

config:
  overlays:
    styles:
      lane:         {kind: fill, opacity: 1, width: 0}
      connector:    {kind: fill, opacity: 1, width: 0}
      divider:      {kind: line, color: "#f4f4f4", width_m: 0.2, dash: [15, 45], min_zoom: 17}
      centre:       {kind: line, color: "#f4f4f4", width_m: 0.2, min_zoom: 17}
      zebra:        {kind: fill, color: "#f7f7f2", opacity: 1, width: 0, min_zoom: 16}
      lane_arrow:   {kind: fill, color: "#f4f4f4", opacity: 1, width: 0, min_zoom: 18}
      street_name:  {kind: text, text_col: name, text_size: 12, text_color: "#f4f4f4", text_halo: "#3a3a3a", min_zoom: 17}

Theme Field Reference

Field Type Applies To Description & WebGL Shader Translation
kind str All WebGL primitive type: fill (polygons), line (strokes), circle (points), or text (labels).
color str fill, line, circle Color hex code (e.g. "#f4f4f4"). Can be overridden per-feature by color_col.
opacity float All Visual opacity from 0.0 (transparent) to 1.0 (fully opaque).
width float line, fill Fixed screen width in device pixels.
width_m float line Physical width in ground meters (e.g. 0.20 for a 20cm line). Scaled dynamically by the Web Mercator zoom formula!
dash list[float] line Dash pattern in multiples of line width (e.g. [15, 45] $\to$ 3m dash, 9m gap on 20cm line). Compiles to line-dasharray.
min_zoom float All Camera zoom level where layer first turns on. Compiles to MapLibre minzoom.
max_zoom float All Camera zoom level where layer turns off. Compiles to MapLibre maxzoom.
text_col str text Feature property containing the string to display (e.g. name $\to$ ["get", "name"]).
text_size float text Font size in screen points (default: 12).
text_color str text Font fill color (e.g. "#f4f4f4" for white road markings).
text_halo str text High-contrast outline halo around glyphs (e.g. "#3a3a3a" with 1.5px width) for readability on dark asphalt.
⚖️ Geometry Settings (lanestyle.json) vs. Visual Styles (lanestyle.yaml)
Clear separation between physical Python spatial math and GPU rasterization rules.
Physical / Python Space

lanestyle.json (Geometry Settings)

Controls coordinate generation and spatial calculations in Python:

  • Arrow Dimensions: length_m: 4, repeat_m: 60, end_m: 10.
  • Street Name Clearance: names: {clear_m: 3} (cuts the street name centerline 3 meters away from painted arrows and zebras).
  • Lane Widths: default_width_m: 3.25, walk: 2.0, bike: 1.5.
  • Curb Casings: casing_m: 0.14, junction_trim_m: 1.0.
Screen / GPU Space

lanestyle.yaml (Visual Theme)

Controls WebGL fragment shaders and zoom visibility on the screen:

  • Zoom Activation: Turns street names on at min_zoom: 17, arrows at min_zoom: 18, zebras at min_zoom: 16.
  • Typography: Font size 12px, white text #f4f4f4, dark halo #3a3a3a.
  • Shader Placement: symbol-placement: "line-center".
  • Line Dashes: dash: [15, 45] for white lane dividers.
📞 The Python Calling Contract & Precedence Rules
How an Overlay binds to its style and how argument overrides work.
# 1. lanestyle loads theme YAML and merges into roadstyle settings
rs_settings = _merge(lane_theme(), _ROADSTYLE)

# 2. Overlays reference style names:
overlays = [
    # References style="street_name" from YAML (kind: text, min_zoom: 17)
    rs.Overlay(names, edge_col="road_id", order_col="order", style="street_name"),

    # References style="lane_arrow" from YAML (kind: fill, min_zoom: 18)
    rs.Overlay(arrows, edge_col="road_id", order_col="order", style="lane_arrow"),

    # Direct override: explicit arguments win over the YAML style!
    rs.Overlay(special_labels, edge_col="road_id", style="street_name", text_color="#f59e0b")
]

# 3. roadstyle compiles the unified MapLibre WebGL style JSON
m = roadstyle.render_edges(roads, overlays=overlays, settings=rs_settings)
The Precedence Hierarchy
Explicit Overlay(...) argument > Theme style in YAML (config.overlays.styles) > roadstyle engine default.

🐍 Primary Compiler Entry Point
Compiling primitives into a self-contained WebMap.
from roadstyle.v2 import Corridor, Channel, Demarcation, ViewPreset, compile_map

# 1. Define Corridors
corridors = [
    Corridor(
        geometry=road_line,
        width_m=10.5,
        casing_left_m=0.30,
        casing_right_m=0.15,
        split_start=12.0,   # Asymmetric 12m junction setback at node u
        split_end=4.0,      # Asymmetric 4m setback at node v
        fill_visible=False  # Hollow container for child lanes
    )
]

# 2. Compile Map
map = compile_map(
    corridors=corridors,
    channels=lanes,
    demarcations=markings,
    presets=[
        ViewPreset(name="Physical", width_mode="physical", color_by="class"),
        ViewPreset(name="Flow", width_mode="flow", width_by="volume")
    ]
)

# 3. Save or Serve
map.save("network.html")
