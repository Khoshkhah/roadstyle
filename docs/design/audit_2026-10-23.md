## roadstyle Rust engine: audit of efficiency and modularity opportunities

I read `origin/rust-engine` at commit `0ba68d7` and changed nothing in any repository. To read the code, I extracted a copy to a private folder outside the repo.

- Paths with no folder in front are in the repository on that branch.
- The browser consumer is in duckosm-rust's `crates/duckosm-wasm/www/`.
- The "measured" sizes come from the golden style `rust/roadstyle-rs/tests/data/monaco_part/plain.json.gz`. It is simple mode, 1,373 roads and 1,855 pieces. Rust writes this style byte for byte.

**A key measurement.** No MapLibre layer reads many `__rs_*` keys, and the dashboard (`src/roadstyle/static/dashboard/*`, the page templates) does not read them either. `rsGetProps` removes every key that starts with `_`, so these keys are internal by contract. The only reader is the old Leaflet `roadstyle.js`. In the `simple` source, 315 KB of 1,081 KB (29 %) is unread keys. In the `roads` source, 227 KB of 1,367 KB (17 %) is unread keys. The keys are `__rs_class`, `__rs_oneway`, `__rs_op`, `__rs_cop`, `__rs_w`, `__rs_cw`, `__rs_band` (always 0), `__rs_cl`, `__rs_fl`, `__rs_cs`, `__rs_ce`, `__rs_twin`, `__rs_cap0`, `__rs_cap1`, `__rs_split`, `__rs_stub` and `__rs_main`. Also, `__rs_cls` (41 KB) has the same value as `highway` when `filter_col` is not given.

### Top 5 to do next, in this order

1. **R5: decide on the full look.** The decision costs little and deleting the code is small. It removes about 900 lines and one of the two drawing paths. It also unblocks R1, because only `full.rs` reads `__rs_cl`, `__rs_cs`, `__rs_ce` and `__rs_band`, and it makes R7 smaller.
2. **R2: run stage 1 one time (with f).** This is the largest time gain: one Tartu style is 5.1 s, and a tiled page or a page with views runs stage 1 two or more times today. It is also the first real user of the stage border that f plans.
3. **R1 + R8: declare what each layer and module reads, and stop writing the rest.** This is the largest measured size gain: 29 % of the `simple` source and 17 % of the `roads` source. It applies to GeoJSON and tiles alike, and it adds no new data path. It needs one parity decision for the Python goldens.
4. **R4 with R13: one topology, built from duckOSM's node ids when they are present.** Nine end-point maps with three snap rules become one index. The SQL change (R13) is small and keeps `source`/`target`. Restyle, typed slots and R11 build on this topology.
5. **R3: a typed stage 3 (the page).** After f, the page can take typed parts. This removes three full serializations of the style and about 37 copies of the page, and it declares the dashboard options in one place in place of five.
