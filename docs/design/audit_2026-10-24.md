**The layering rules and Kaveh's requirements**

- Rule 1 (the core knows no JavaScript): N1 and the 2^53 rule in the model break it. The core crates do no other I/O; they use only `io::Write`.
- Rule 5 (no page options in the engine): `contract::controls` and `page_state`, and the `tiles`, `views`, `pitch_3d` and `select_color` values in `contract.rs:116-145`, are page options in the engine.
- Rule 6 (one copy of each rule): N3, N4 and N7 break it.
- "Two public stages with a GeoJSON/GeoParquet border": N2, N5 and N6 work against it. N1 breaks the BIGINT rule at that border.
- "One road table for both ways": done for the Rust pages. N2 and N14 are still against it.
- "Python is the reference until P7": `live_data`, `export_geojson`/`tile_geojson` and the GeoParquet road table are Rust only (`render.py:127-128`, `export.py:35-60`). No parity golden covers them. Record this in the plan.
- "Simple mode only": the engine follows it. The JS branches remain (N16).
- "Every part in Rust": the CLI still depends on Python's files (N11).
- On R12 (in progress), a comment: the global levels cache hides the cost of R2. It does not remove it. It also keeps 2 `Levels` in the wasm memory for the life of the page.

### 3. Top 5 to do next, in this order

1. **N1, BIGINT ids at the GeoParquet border.** This is a small change and a real data error. It breaks the rule that all matchers join on BIGINT. Do it before more users read `road_table.parquet`.
2. **N3, one stage-2 call.** It is small. It removes 3 of the 4 vector-style builders and fixes the missing `promoteId` in `make_tiled`. N7 and N2 then have one place to change.
3. **N7, one metadata writer for roles, arrows and live.** It is small. It fixes the stale roles in tiled live styles and the metadata keys that no code writes. Hosts outside Python (duckosm-rust, the examples) then work without patches.
4. **N2, stage 1 independent of the `tiles` and `state` switches.** This is the core of Kaveh's "two stages, one road table" requirement. It removes 52 % of the style for hosts that are not pages, and the patches in both examples. It needs one parity decision for Python.
5. **N4 with R1, a lean road table.** This is the largest measured size gain in each page (−42 % raw, −33 % gzipped of the props). It fits into the R1 work now in progress. N6 and N5 come after it, because R2's restyle needs a stage-1 output that can be used again.
