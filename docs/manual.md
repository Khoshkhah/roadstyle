# Manual

One walk-through of the library, top to bottom, with the **actual rendered map embedded after the
key steps**. Each embedded map is the real, self-contained output of the snippet above it,
regenerated by
[`docs/build_maps.py`](https://github.com/Khoshkhah/roadstyle/blob/main/docs/build_maps.py) from the
bundled sample edges (`notebooks/data/sodermalm_edges.gpkg`, ~4,600 real road edges). Every snippet
uses a GeoDataFrame of road edges called `edges`; the [notebooks](#notebooks-example-scripts) run
the same material in Jupyter.

Install first ([Home](index.md#install)); every keyword is in the [Parameter reference](parameters.md).

---

## 1. Your first map

Load road edges and render. `backend="web"` is the default: a self-contained MapLibre map you can
ship as one file, opening from disk with no server and no internet.

```python
import geopandas as gpd
import roadstyle as rs

edges = gpd.read_file("sodermalm_edges.gpkg")        # has a `highway` column
rs.render_edges(edges).save("first_map.html")         # web backend, Voyager base (settings default)
```

You get the OSM "geometry sandwich" (coloured fills over casings), per-zoom widths, two-way lanes,
one-way arrows, street-name labels, hover/click, and a base-layer switcher — try them in the map.
Prefer a dark canvas? Pass `basemap="dark_matter"` (Dark Matter) or `basemap="satellite"`.

<iframe src="../maps/first_map.html" loading="lazy" title="A first roadstyle map"
        style="width:100%;height:480px;border:0;border-radius:10px;box-shadow:0 2px 12px rgba(0,0,0,.18)"></iframe>

*Hover a road to highlight it; click it for its attributes; use the base-map button (bottom-right)
to switch the base map.*

`render_edges` returns a `WebMap` (`.save(path)`, `.html` for the page as a string), a
`folium.Map` with `backend="folium"`, or a `lonboard.Map` with `backend="lonboard"`. In a notebook
each displays inline. The in-map UI toggles with `arrows`, `labels`, `filter_control` and
`basemap_switcher` (all default `True`).

### What the edges need

- **Line geometry** (LineString / MultiLineString), in any CRS: it is reprojected to EPSG:4326 and
  non-line rows are dropped.
- **A road-class column**, `highway` by default (another name: `highway_col=`).
- Optional columns switch features on: `name` (labels, popup title), `oneway` (arrows),
  `tunnel` / `bridge` / `layer` (grade separation: tunnels draw underneath, bridges on top),
  `edge_id` (kept exact past 2\*\*53). Every other column shows in the popup.
- An edge is **directed**: its geometry runs the way traffic flows, and a two-way road is two edges
  with reversed geometry, drawn side by side.

Class column under another name? `normalize_edges` renames it (and does the reprojection) up front:

```python
edges = rs.normalize_edges(raw, class_col="highway", rename={"vagtyp": "highway"})
```

### Palettes and base maps

The palette sets the per-class road colours: `highsat` (high contrast, the default), `carto`
(classic OSM) or `mono` (grey, the base for data colouring). The base map sets the background: any
key in `rs.BASEMAPS` (`voyager`, `positron`, `dark_matter`, `osm`, `esri_gray`, `satellite`, the
tile-less `blank` / `blank_dark`, …), and `basemaps=` picks what the switcher offers.

```python
rs.render_edges(edges, palette="carto", basemap="positron")
rs.render_edges(edges, basemap="dark_matter", basemaps=["dark_matter", "positron", "satellite"])
```

xyzservices providers, tile URLs, your own base maps and API keys (CARTO shows a watermark without
one): [Palettes → Base maps & API keys](palettes.md#base-maps-api-keys).

## 2. Colour roads by your own data — switchable, in the browser

Any column can drive the colour, categorical or numeric, and the web map draws the legend
(`legend=True` is the default). For **one** colouring pass the styler keywords straight to
`render_edges`:

```python
# categorical: one colour per value, nothing to register
major  = {"motorway", "trunk", "primary", "motorway_link", "trunk_link", "primary_link"}
medium = {"secondary", "tertiary", "secondary_link", "tertiary_link"}
edges["importance"] = edges["highway"].apply(
    lambda h: "major" if h in major else "medium" if h in medium else "minor")
rs.render_edges(edges, color_by="importance",
                colors={"major": "#ef4444", "medium": "#f59e0b", "minor": "#64748b"})

# numeric: a colour ramp, plus a width ramp from 1 to 6 px across the value range
rs.render_edges(edges, color_by="maxspeed_kmh", cmap="viridis", vmin=20, vmax=90, width_by=(1, 6))
```

`cmap` is any matplotlib / branca colormap name, `vmin` / `vmax` clamp the range. Numeric styling
needs the `numeric` extra (`pip install "roadstyle[numeric]"`).

Colours you computed yourself go in per edge: `color_table` maps `edge_id` to a colour (a dict,
Series or DataFrame; misses fall back to grey), and `colors="self"` reads a colour column as-is.

```python
rs.render_edges(edges, color_table={edges.edge_id[0]: "#e6194B", edges.edge_id[1]: "#3cb44b"})
rs.render_edges(edges, color_by="color", colors="self")      # `color` already holds "#rrggbb"
```

Bake **several "colour by" options** into one map and switch between them client-side, with no
re-render and no server. Pass `color_options` — an ordered `{name: {styler kwargs}}` mapping — and
roadstyle adds a **Colour by** dropdown. A neutral base reads best, so pair it with
`palette="mono"`:

```python
rs.render_edges(edges, backend="web", palette="mono",
    color_options={
        "Class": {},                                       # neutral mono base
        "AADT":  {"color_by": "aadt",  "cmap": "viridis"},
        "Speed": {"color_by": "speed_kph", "cmap": "magma"},
    },
).save("recolor.html")
```

<iframe src="../maps/recolor.html" loading="lazy" title="Switchable data-driven colouring"
        style="width:100%;height:480px;border:0;border-radius:10px;box-shadow:0 2px 12px rgba(0,0,0,.18)"></iframe>

*Use the **Colour by** dropdown (top-right) to switch between road class, AADT, and speed. The legend
(bottom-left) follows the active option. Roads keep their width/casing/lanes — only the fill swaps.*

Two things worth knowing:

- **Blank edges keep the base colour.** An edge with no value for a data option (NaN / unmapped)
  falls back to its **base (mono) colour**, not a flat grey — so "no data" roads blend into the base
  instead of reading as a separate category.
- **Drive it from your own UI.** The page exposes `window.rsSetColorField(name|index)` and fires a
  `rs:colorchange` event, so a custom control can switch colours and stay in sync (see
  [§5](#5-drive-the-map-from-your-own-ui)).

## 3. Filter and highlight

Keep or drop road classes. `match_links=True` (the default) keeps `*_link` ramps with their parent.

```python
sorted(rs.highway_types(edges))                               # which classes are present?
rs.render_edges(edges, include=["motorway", "trunk", "primary"])
rs.render_edges(edges, exclude=["service", "footway", "path", "cycleway"])
```

A neon highlight of a sub-selection is `selected=`, on `backend="folium"` only (the web backend
ignores it):

```python
rs.render_edges(edges, backend="folium", selected=edges[edges["highway"] == "secondary"])
```

On the web map, highlight from JavaScript instead: `rsColor(rsQuery(p => ...), "#e63946")` recolours
a set, `rsHighlight(ids)` gives it the selection glow ([§5](#5-drive-the-map-from-your-own-ui)).

## 4. Add your own overlay layers (zones, POIs, anything)

Bring extra geometry — zone polygons, POI points, any lines — as `Overlay`s. Each becomes its own
layer drawn **under** or **over** the roads, clickable for a popup of the fields you list, and
toggled from a **Layers** control. Overlays are *your* data with *your* style; they don't go through
the road-styling compiler.

```python
from shapely.geometry import box, Point

# (here: synthetic zones + POIs — in practice your own GeoDataFrames)
rs.render_edges(edges, backend="web", palette="mono",
    overlays=[
        rs.Overlay(taz,  kind="fill",   placement="under", color="#6aa9ff",
                   opacity=0.14, label="TAZ zones", popup=["taz_id", "name", "weight"]),
        rs.Overlay(pois, kind="circle", placement="over",  color="#ff5d5d",
                   radius=7, label="POIs", popup=["name", "type"]),
    ],
).save("overlays.html")
```

<iframe src="../maps/overlays.html" loading="lazy" title="Overlay layers — zones and POIs"
        style="width:100%;height:480px;border:0;border-radius:10px;box-shadow:0 2px 12px rgba(0,0,0,.18)"></iframe>

*Translucent **TAZ zones** sit under the roads; red **POIs** sit on top. Click a zone or a POI for
its popup; use the **Layers** control (bottom-right) to toggle each overlay. (What's drawn on top wins
the click: a POI (`placement="over"`) before the roads, the roads before a zone underneath.)*

`kind` is auto-detected from the geometry (polygon → `fill`, point → `circle`, line → `line`) but can
be forced. See [`Overlay`](parameters.md#overlay-extra-layers) for every field.

## 5. Drive the map from your own UI

Both web outputs let you build a **custom panel** instead of (or alongside) the built-in controls.

**Web backend (`render_edges(backend="web")`).** The page exposes `window.rs*` globals you can call
from any HTML you add to it (`m.html` is the page as a string; append before `</body>`):

```html
<button onclick="rsSetColorField('AADT')">AADT</button>
<script>
  document.addEventListener("rs:colorchange", e => console.log("now showing", e.detail.option.name));
</script>
```

`window.RS_COLOR_OPTIONS` lists the baked options; `window.rsSetColorField(name|index)` recolours;
`rs:colorchange` fires on every switch. `rsQuery`, `rsColor`, `rsHighlight`, `rsSelect`, the
`rs:select` event and the rest are in [the JavaScript API](web-backend.md); copyable panels are in
[`ui/`](https://github.com/Khoshkhah/roadstyle/tree/main/ui). (A worked custom-panel page is in
[`examples/recolor_web_backend.py`](https://github.com/Khoshkhah/roadstyle/blob/main/examples/recolor_web_backend.py).)

**roadstyle.js spec page (`rs.save(...)` / `to_html`).** Python computes the styling once, and the
bundled `roadstyle.js` draws it in your own page, with no Python at runtime. Its `RoadStyleMap` API
has a real panel hook + event bus:

```js
const m = RoadStyle.create("map", spec, { widgets: { colors: false } });
m.on("ready", map => {
  map.addPanel({ title: "Colour by", position: "topright", render(body, map) {
    map.getColorOptions().forEach((o, i) => {
      const b = document.createElement("button");
      b.textContent = o.name; b.onclick = () => map.setColorField(i);
      body.appendChild(b);
    });
  }});
});
```

`addPanel` gives you styled, auto-stacking chrome; `on("select"|"deselect"|"colorchange"|"ready", …)`
is the event bus; `setColorField` / `getColorOptions` drive the recolour. Selection is single:
another click replaces it; clicking the same road or the background clears it.

The renderer ships inside the package; copy it next to your spec:

```python
import shutil
from importlib.resources import files

rs.save_spec(rs.to_spec(edges, basemap="dark_matter"), "web/map_data.json")
for asset in ("roadstyle.js", "roadstyle.css"):
    shutil.copy(files("roadstyle") / "static" / asset, f"web/{asset}")
```

Browsers block `fetch()` from `file://`, so loading `map_data.json` by URL needs the folder served
(`python -m http.server`); for a page that opens with a double-click, pass the spec object to
`load()` instead of a URL (notebook 05). The full API is in
[Embedding in a website](embedding.md); a worked page is
[`examples/recolor_custom_panel.py`](https://github.com/Khoshkhah/roadstyle/blob/main/examples/recolor_custom_panel.py).

## 6. Loading data

Everything funnels through `as_edges`, so `render_edges` / `to_spec` take more than a
GeoDataFrame. Pass whatever you already have:

```python
rs.render_edges(gdf)                 # a GeoDataFrame
rs.render_edges("roads.gpkg")        # a file path: GeoPackage / GeoJSON / Shapefile / …
rs.render_edges(feature_collection)  # a GeoJSON mapping, a to_spec() dict, or __geo_interface__
rs.render_edges(arrow_table)         # a pyarrow Table (GeoArrow works directly)
```

For a plain WKB / WKT geometry column, a source CRS or a renamed class column, use the matching
helper and pass its result on (each returns a `RoadEdges`):

```python
import pyarrow as pa

# pyarrow with a WKB column
table = pa.table({"highway": edges["highway"].astype(str).tolist(),
                  "geometry": [g.wkb for g in edges.geometry]})
rs.render_edges(rs.from_arrow(table, geometry="geometry", crs=edges.crs))

# DuckDB: select the geometry as WKB (ST_AsWKB) or WKT (ST_AsText) so it round-trips.
# DuckDB carries no CRS, so crs= says what the coordinates are in.
e = rs.from_duckdb(con, "SELECT highway, aadt, ST_AsWKB(geom) AS geom FROM roads",
                   geometry="geom", crs=3006)
rs.render_edges(e, color_by="aadt", cmap="YlOrRd")
```

| You have… | Just pass it | For options use |
|---|---|---|
| GeoDataFrame / `RoadEdges` | `render_edges(gdf)` | `normalize_edges` |
| a file | `render_edges("roads.gpkg")` | `load_edges` (`layer=`) |
| GeoJSON / spec | `render_edges(fc)` | `from_geojson` |
| pyarrow Table | `render_edges(table)` | `from_arrow` |
| DuckDB | — | `from_duckdb` |

DuckDB and pyarrow need the `duckdb` / `arrow` extras.

## 7. Large datasets

The web backend inlines every edge as GeoJSON, comfortable to ~10⁴ edges. Towards ~10⁵ pass
`tiles=True` (embedded vector tiles in the same single file, the `tiles` extra). For millions, switch to
**lonboard** (deck.gl / WebGL, the `lonboard` extra): same call and styling, on the GPU, with fewer
cartographic touches.

```python
rs.render_edges(edges, tiles=True)
rs.render_edges(edges, backend="lonboard", color_by="length_m", cmap="magma", width_by=(1, 5))
```

Which to pick, feature by feature: [Choosing an engine](engines.md).

## 8. Outputs for the web

Besides the `web` map, the same styling leaves roadstyle as the **canonical JSON spec** (`spec/1`):
your data plus the baked per-edge style, for any frontend to draw.

```python
spec = rs.to_spec(edges, basemap="dark_matter", color_by="highway")   # canonical JSON dict
rs.save_spec(spec, "map_data.json")                                    # round-trips with load_spec()
gj = rs.to_geojson(edges, color_by="highway")                          # just the styled features
rs.save(edges, "standalone.html", basemap="dark_matter")               # roadstyle.js page
html = rs.to_iframe(edges, basemap="dark_matter", height="360px")      # an <iframe> string, zero JS
```

`save_spec` / `save` / `to_iframe` take a spec or the edges plus `to_spec` keywords. Each feature
carries reserved `__rs_*` properties (`__rs_fill`, `__rs_w`, `__rs_casing`, …), so the browser never
needs roadstyle's styling logic. The property contract and Leaflet / MapLibre snippets:
[Embedding in a website](embedding.md).

## 9. Custom (non-OSM) road classes

For a class vocabulary that isn't OSM `highway` (NVDB functional classes, say), register a palette
of `RoadStyle(fill, width, casing_width)` entries and style by that column:

```python
from roadstyle import register_palette, RoadStyle, color_by_class

register_palette("nvdb", {"0": RoadStyle("#00E5FF", 6, 8),
                          "1": RoadStyle("#FF9100", 4.5, 6.5)})
rs.render_edges(edges, style=color_by_class("functional_road_class",
                                            palette="nvdb", normalize_links=False))
```

`save_palette` / `load_palette` keep a palette as JSON, so a non-coder can edit the colours or a
web frontend can share them. Colours, widths, casing and camera defaults are *settings*, not
keywords (`render_edges(edges, settings={...})`): see
[Palettes → settings](palettes.md#customising-data-files-and-overrides).
